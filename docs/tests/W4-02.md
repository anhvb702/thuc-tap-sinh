# W4-02 — Sao lưu và khôi phục dữ liệu JSON

## Hợp đồng nghiệm thu

### Mục tiêu

Cho phép người dùng lưu snapshot dữ liệu SQLDelight ra JSON trên máy và khôi phục snapshot đã chọn, không cần tài khoản, mạng hoặc quyền storage đặc biệt. Chọn nơi lưu/mở bằng Android Storage Access Framework.

### Payload v1

```json
{
  "format": "yourrefri-backup",
  "version": 1,
  "pantry": [],
  "shelfOverrides": [],
  "quantities": [],
  "cookLogs": []
}
```

- `pantry`: mọi dòng `PantryEntity`, kể cả `have=false`, cùng `markedAt` ISO. Giữ được khác biệt giữa chưa từng có dòng và đã đánh dấu “Hết”.
- `shelfOverrides`: mọi `UserShelfEntity`, gồm giá trị `0`.
- `quantities`: chỉ ghi override `PantryQuantityEntity` (`quantity > 1`); quantity mặc định `1` không tạo dòng.
- `cookLogs`: `id`, `recipeId`, `cookedOn`, `photoUri`, `savedIngredientIds`; giữ id để bảo toàn thứ tự nấu cùng ngày. Chỉ giữ chuỗi URI ảnh làm metadata; file ảnh không được đưa vào bản sao lưu.
- Không backup catalog tĩnh hoặc cài đặt nhắc nhở vì các dữ liệu này không nằm trong bảng SQLDelight hiện tại.
- Không thêm dependency. Codec strict: từ chối JSON sai cú pháp, field lạ, sai format/version, ngày không hợp lệ, ID rỗng/trùng, shelfDays âm, quantity <= 1, CookLog id <= 0, hoặc saved id rỗng/chứa dấu phẩy.
- Toàn bộ payload phải decode/validate trước khi đụng DB. Khôi phục xóa và chèn mọi bảng trong một transaction; mọi lỗi giữ nguyên toàn bộ dữ liệu trước đó.

### Codec — commonMain/commonTest

API đề xuất: `BackupCodec.encode(snapshot)` và `BackupCodec.decode(json)`, với DTO `PantryBackupSnapshot`, `PantryBackupItem`, `ShelfOverrideBackup`, `QuantityOverrideBackup`, `CookLogBackup`.

| Test | Input | Expected Output | Mutation bắt |
| --- | --- | --- | --- |
| `encode_includesEveryPersistentField` | snapshot có pantry `have=false`, shelf 0, quantity, cook log URI/list | JSON giữ đúng mọi trường | bỏ nhóm/trường |
| `decode_roundTripsAndPreservesOrdering` | snapshot hợp lệ, nhiều log cùng ngày | DTO giống hệt và giữ thứ tự/id | bỏ id/đảo sort |
| `decode_emptySnapshot_returnsEmptyTables` | bốn mảng rỗng | snapshot rỗng hợp lệ | fallback sai |
| `decode_rejectsUnsupportedVersionOrFormat` | version/format sai | lỗi, không trả snapshot mặc định | bỏ kiểm version |
| `decode_rejectsMalformedJsonUnknownFieldsAndInvalidDate` | JSON sai, field lạ, ngày sai | lỗi rõ | decode lỗi thành rỗng |
| `decode_rejectsDuplicateIdsAndInvalidValues` | ID trùng/rỗng, shelf âm, quantity <= 1, CookLog id <= 0 | lỗi | bỏ validation |
| `decode_rejectsSavedIdsUnsupportedByAdapter` | id rỗng/chứa dấu phẩy | lỗi | lưu payload gây lỗi DB |

### Repository — androidUnitTest

| Test | Input | Expected Output | Mutation bắt |

### Android SAF / UX

- Export dùng `CreateDocument("application/json")`, gợi ý tên `yourrefri_backup.json`; người dùng chọn Downloads hoặc nơi lưu khác trong picker.
- Restore dùng `OpenDocument` với MIME JSON; đọc toàn bộ và validate trước khi hỏi xác nhận thay dữ liệu hiện tại.
- Chỉ khi người dùng xác nhận mới gọi restore transaction. Báo thành công sau khi stream đóng/DB commit; lỗi hiện lời nhắc ngắn, không báo thành công giả.
- Không xin `READ/WRITE_EXTERNAL_STORAGE`, không tự ghi vào đường dẫn Downloads.

### Chia stage

1. Codec + common tests (test đỏ trước implementation).
2. SQLDelight export/restore repository + in-memory tests; thêm `deleteAll`/`insertWithId` queries, không đổi schema.
3. Android SAF + Settings UI + xác nhận restore. Không sửa hai agent cùng file; Gradle chạy từng stage theo hàng đợi.
