# A-16 — Phase 1: diet safety, cook undo/history delete, weekday reminder

## Contract

- **Task ID:** A-16.
- **Inputs:** `recipes`, selected `DietRestriction`, pantry ingredients; cook action with current `PantryGridState`, candidate ingredient IDs and cook-log callback; delete action with a `CookLog.id`; reminder `enabled`, `now`, `TimeZone`, optional Sunday and weekday `LocalTime`; stored reminder preference minutes.
- **Expected output:** `MainScaffold.visibleRecipes` is always `filterRecipesByDiet(...)`, and the recipe random pool is the same filtered list. When empty, recipes remain empty and the UI shows an empty state/notice.
- Finishing a cook consumes all currently available main ingredients immediately. “Giữ lại đồ còn dư” opens `CookLeftoverDialog` and ingredients marked as kept are excluded. Undo is available for five seconds; choosing it restores the pre-cook pantry quantity/marked date and deletes the log created by that cook.
- A history row exposes delete and dispatches `CookHistoryAction.Delete(log.id)` to `CookLogRepository.delete`.
- Weekday reminder default is 15:30; Sunday remains independently customizable. Custom weekday minutes are stored under `weekday_minutes` in `daily_reminder`, and both custom times affect the next local wall-clock trigger.

## Edges and risks

- Empty filtered recipe list, empty candidate list, duplicate candidate IDs, ingredient no longer in pantry, quantity greater than one, failed/null cook-log result, exact reminder time, invalid preference minutes and DST boundaries.
- If a cook-log write fails, Undo can still restore the pantry but there is no log ID to delete.
