# PH4-04 — Undo, cook preview, history restore, pantry clarity

## Contract

- `recipeCookPresentation`: preview names exactly the available ingredient IDs that cooking deducts; empty selection says no ingredients will be deducted. Leftover selection remains optional and its label states that unselected ingredients are not deducted.
- Cook and pantry undo snackbar remains available for 30 seconds unless replaced/dismissed by a new action.
- Deleting a cook history row offers restore-and-delete. Confirming restores every saved ingredient to `have = true` and removes that cook log; cancelling changes neither.
- Pantry location chips select All/Fridge/Freezer. Item status communicates the one-tap action. Switching compartment reports old and new estimated days, with an edit-shelf-days action.

## Observable tests

- Preview presentation tests: matching available ingredients and empty selection; assert exact preview copy and IDs.
- CookHistoryViewModel tests: restore-and-delete forwards the log's saved IDs for restoration and deletes only the selected row; ordinary delete does not restore.
- PantryGridPresentation tests: location filters and status action labels for present/missing items; compartment estimate message shows old-to-new days and edit action.
- UI copy tests: leftover label and custom ingredient action are visible, and no emoji appears.

## Six mutations

1. Preview all recipe ingredients instead of only available/deducted IDs.
2. Omit the empty-preview message.
3. Restore IDs but retain the log row.
4. Delete log without restoring saved IDs.
5. Map fridge and freezer chips to the same compartment.
6. Omit old or new estimated days from compartment feedback.
