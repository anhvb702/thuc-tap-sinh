# W6-01 — Weekly meal planner contract

## Contract

- **Task ID:** W6-LOGIC. Pure shared logic; no database, clock, UI, or recipe bundle format changes.
- **Inputs:** `Recipe` list, `PantryGridState` (catalog order and `have` flags), `DietGoal`, preference tags, and per-day swap offsets. Shopping consumes a plan and the same state; stocking consumes shopping rows and unchecked IDs.
- **Expected output:** Up to seven Monday–Sunday rows, selected deterministically from distinct recipe IDs. Adjacent days never share an ID; unseen recipes are preferred before repeating. Early days favor available ingredients estimated for use within 0–2 days or a cookable recipe. Goal/preference ingredient/time matches affect selection. Shopping counts each required slot once per meal, chooses the first available alternative or otherwise the first alternative, sorts missing items before pantry items in catalog order, and stocking returns only checked missing IDs.
- **Boundary/risk:** Empty recipe input yields no plan. Shopping ignores unknown ingredient IDs absent from catalog. Optional slots do not contribute. A one-recipe catalog cannot satisfy the adjacent-day rule for every day; it is emitted once.

## Tests

| Test | Input | Observable expected result |
|---|---|---|
| `buildsSevenDaysWithoutAdjacentRepeats` | 3 recipes, default state | 7 labeled days; no neighboring IDs equal |
| `swapOffsetSelectsNextEligibleRecipe` | 3 recipes, offset day 0 by 1 | Day 0 advances to next candidate |
| `quickGoalPrefersAtMostTwentyMinutes` | quick and slow recipes | quick recipe selected first |
| `earlyDaysPreferUrgentPantryIngredients` | urgent cookable recipe and unrelated recipe | urgent recipe is selected on day 0 |
| `shoppingUsesAvailableAlternativeAndCountsMeals` | same two-slot recipe twice; second alternative available | available alternative row has mealCount 2 and pantry flag true |
| `shoppingSortsMissingBeforePantryAndStockFiltersUnchecked` | catalog order differs from recipe slot order | missing rows first in catalog order; stock IDs exclude pantry and unchecked |

## Six mutation probes

1. Reverse the `daysLeft in 0..2` check: `earlyDaysPreferUrgentPantryIngredients` must fail.
2. Change quick threshold `<= 20` to `< 20`: `quickGoalPrefersAtMostTwentyMinutes` must fail at boundary.
3. Remove adjacent-ID exclusion: `buildsSevenDaysWithoutAdjacentRepeats` must fail.
4. Ignore `swappedOffsets`: `swapOffsetSelectsNextEligibleRecipe` must fail.
5. Always select `slot.anyOf.first()` even when another alternative is present: `shoppingUsesAvailableAlternativeAndCountsMeals` must fail.
6. Include pantry/unchecked IDs when stocking: `shoppingSortsMissingBeforePantryAndStockFiltersUnchecked` must fail.
