# P12-03 — Trang chủ mở đúng công thức đã chạm

## Hợp đồng

**Mục tiêu:** Khi chạm thẻ món ăn thứ hai/thứ ba ở Trang chủ, người dùng nhìn thấy chính công thức đó trong tab Món ăn.

**Input:** Recommendation list, ID của thẻ được chạm, ID null/không tồn tại, tab hiện tại, duration filter mặc định.

**Expected Output:**

- Thẻ truyền ID của chính recipe qua MainScaffold; RecipeScreen chọn đúng ID.
- Mở công thức qua thẻ Home sẽ bỏ lọc thời lượng nếu cần và cuộn thẻ được chọn vào viewport.
- Link chung “Xem công thức” không giữ ID của lần chạm Home cũ; điều hướng tab bình thường tiếp tục mặc định an toàn.
- ID không tồn tại fallback về recipe đầu tiên hiện có; danh sách rỗng không crash.
- Danh sách đề xuất và thứ tự ranking không thay đổi.

## Sáu mutation

1. Luôn chọn ID recipe đầu tiên.
2. Bỏ truyền ID qua MainScaffold.
3. Dùng ID của thẻ trước/sai ở vị trí 2 hoặc 3.
4. Không fallback với ID không tồn tại/rỗng và gây lỗi.
5. Link chung giữ ID trước đó.
6. Không bỏ filter hoặc không cuộn card được chọn vào viewport.

## Bằng chứng

### Test-first và kiểm chứng

- RED: trước khi thêm `resolveInitialRecipeId`, chạy `:composeApp:testDebugUnitTest --tests 'com.loitu.yourrefri.feature.recipe.ui.RecipeSelectionTest'`; biên dịch test thất bại vì helper chưa tồn tại (4 unresolved references).
- GREEN: sau khi triển khai, focused suite có 9 test; chạy lại thành công.
- Full suite cuối: `:composeApp:testDebugUnitTest --rerun-tasks` — `BUILD SUCCESSFUL`, 41 tasks executed. Gradle XML có 9 test `RecipeSelectionTest`.
- Điều hướng thẻ truyền đúng ID qua callback Home → MainScaffold → RecipeScreen. Yêu cầu ID hợp lệ bỏ duration filter và gọi `bringIntoView()` cho đúng thẻ; ID không hợp lệ fallback recipe đầu tiên, danh sách rỗng trả null.

### Mutation probes

Mỗi mutation được biên dịch và chạy focused suite; tất cả đều làm test thất bại. Sau mỗi probe đã khôi phục source.

1. Resolver luôn chọn recipe đầu tiên — bị bắt bởi test ID thứ hai và thứ ba.
2. Callback thẻ Home trả ID cố định — bị bắt bởi test giữ ID của thẻ.
3. Link chung trả ID thay vì null — bị bắt bởi test xóa target cũ.
4. Scroll predicate bỏ điều kiện đúng thẻ — bị bắt bởi test chỉ cuộn mục tiêu đã chọn.
5. Scroll predicate luôn false — bị bắt bởi test cuộn thẻ được yêu cầu.
6. Resolver trả nguyên ID không tồn tại — bị bắt bởi test fallback, mặc định và danh sách rỗng.
7. Duration-clear predicate luôn false — bị bắt bởi `homeRequest_clearsDurationButGenericRequestPreservesDefault`.

Chưa kiểm tra thao tác chạm trên emulator trong lượt này; kiểm tra wiring trực tiếp thuộc lượt xác nhận emulator của coordinator.
