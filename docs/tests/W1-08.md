# W1-08 — Lưu số lượng thực phẩm bền vững

## Hợp đồng nghiệm thu

### Mục tiêu

Lưu số lượng nút `+` / `−` trong SQLite để số lượng còn nguyên sau khi ViewModel nạp lại. Mỗi món chưa có số lượng lưu riêng hiển thị mặc định `1`. Thay đổi số lượng không tự đổi trạng thái Có/Hết hoặc ngày `markedAt`.

### Quyết định dữ liệu

- Lưu vào bảng riêng `PantryQuantityEntity(ingredientId TEXT PRIMARY KEY, quantity INTEGER NOT NULL)` thay vì `PantryEntity`.
- Không tạo dòng pantry giả cho món chưa đánh dấu Có; bảng số lượng chỉ lưu phần vượt mặc định (`quantity > 1`). Số lượng `1` xóa ghi đè để giữ DB gọn.
- Thêm migration SQLDelight từ schema hiện tại version 1 sang version 2; migration không làm mất dữ liệu pantry, hạn sửa tay hay lịch sử nấu.
- `PantryRepository.observeQuantities()` phát map `ingredientId -> quantity` đã lưu. Mọi ingredient không có khóa trong map dùng số lượng mặc định `1` ở tầng UI.
- `setQuantity(id, quantity)` chỉ nhận số nguyên `>= 1`; giá trị 1 xóa ghi đè, giá trị lớn hơn 1 upsert. Không có giới hạn trên ngoài miền `Int`.

### Data stage

**Input:** SQLite in-memory; repository nhận id và quantity; món có thể chưa có dòng `PantryEntity`.

**Expected Output:**

| Test | Input | Expected Output | Mutations bắt |
| --- | --- | --- | --- |
| `observeQuantities_emptyByDefault` | DB mới | map rỗng | M1, M3 |
| `setQuantity_aboveDefault_persistsAndEmits` | `egg=2`, collect flow | map có `egg -> 2`, flow phát lại | M2, M3 |
| `setQuantity_default_removesStoredOverride` | lưu 2 rồi lưu 1 | map rỗng | M2 |
| `setQuantity_doesNotCreatePantryRowOrChangeExistingPantry` | lưu lượng cho món chưa có và món đã có | pantry chỉ đổi qua API `setHave`; `have`/`markedAt` giữ nguyên | M5, M6 |
| `setQuantity_zeroOrNegative_rejectedWithoutWrite` | quantity 0, -1 | `IllegalArgumentException`, DB/flow giữ nguyên | M4 |
| `schemaMigration_v1ToV2_preservesExistingRows` | tạo schema v1, thêm pantry/shelf/cook rows, migrate | dữ liệu cũ giữ nguyên; bảng quantity dùng được | M6 |

Kiểm chứng UI được thực hiện qua ViewModel/Compose source và unit tests. Persona review chỉ đọc source; chưa có screenshot/runtime review sau khi tăng vùng chạm.

### Sáu mutation bắt buộc

1. Đổi fallback quantity từ 1 thành 0.
2. Bỏ ghi quantity vào SQLite.
3. Bỏ phát cập nhật quantity qua Flow sau khi ghi.
4. Cho phép quantity 0 hoặc âm.
5. Ghi nhầm ID hoặc cập nhật quantity cho mọi ingredient.
6. Làm thay đổi trạng thái/ngày pantry khi ghi quantity, hoặc migration làm mất bảng/dữ liệu hiện hữu.

Biên bổ sung: `increaseQuantity_atIntMax_keepsValueWithoutWrite` bắt lỗi tràn số khi tăng tại `Int.MAX_VALUE`.

### Phân tách công việc

1. **Data stage:** test DB/repository, bảng/migration SQLDelight và API repository.
2. **UI stage:** reducer/state/action/effect, ViewModel, Compose card và fake/test ViewModel.
3. Chạy Gradle test tuần tự sau mỗi stage. Reviewer làm mutation sau khi tích hợp xong; phục hồi code trước lượt test xanh cuối.
